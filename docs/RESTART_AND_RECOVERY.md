## 3. 私人資料應在哪裡找

在**原本持有權限的 Google Drive 帳號**下，找到族譜私人備份根目錄；不要把雲端連結或帳號貼進公開 GitHub：

- `00_目前最新版`：正式 ZIP、MASTER、閱讀版、進度表。
- `01_MASTER歷史`：核准前候選與歷史 MASTER。
- `02_原始來源`：族人填報、照片、證書及其他附件，原始檔不可覆寫。
- `03_里程碑完整包`：舊版完整 ZIP 及里程碑副本。
- `04_系統與接班`：管理工具、部署原始碼、接班與發布相關私人備份。
- `99_CHANGELOG`：變更紀錄、核准證明、QA、校驗資料。

2026-10-19 已核對這些主要資料夾存在，`00_目前最新版` 的四個正式檔存在且顯示未分享。**僅確認雲端檔案存在／大小與權限狀態，不能因此保證其中每一位人物資料都已獨立重新驗證。**

## 4. 日後從零重新接手的順序

1. 先登入原有**私人 Google Drive**，找 `00_目前最新版` 的四個檔；確認 `03_里程碑完整包` 與 `99_CHANGELOG` 仍可讀。
2. 下載完整 ZIP；核對檔案大小與 SHA-256，再解壓、開啟操作入口。若校驗不符，**停止更新**，改比對歷史版本。
3. 在主編指定的 Windows 資料夾（原先為 `D:\族譜`）恢復工作環境；操作以圖形介面、匯入匯出及備份還原為主，不要求主編寫程式或執行 SQL。
4. 查看 `工作步驟與進度追蹤.xlsx`、CHANGELOG、原始佐證及待查項目，**不要以 GitHub README 代替私人進度表**。
5. 需要新增／修正人物時先保留來源、三方核對、標示已證實／口述／待查／衝突；有矛盾須由主編決定，再做新版候選、核准與正式輸出。
6. 如要恢復線上系統，到私人 `04_系統與接班` 取得原部署備份並另做權限與登入驗收。GitHub 空白填報頁、私人 Web App、離線 HTML 閱讀版是**不同系統**；MASTER 更名、Google Drive 備份並不代表網站已重新發布。
7. 正式發布任何含族人資料的版本前，先審查活人隱私、照片刊載同意與閱讀權限；不可將私有資料推送到此公開儲存庫。

## 5. 絕不可憑空補寫或外流

- 對外閱讀檔通常是匯出結果；「介面不可編輯」不等於技術上絕對無法篡改。
- 發布／接班／驗證流程應循私人系統資料與最新測試報告，不臆測舊 RC/Gate 測試是否仍有效。
- 使用者資料只能在合法權限範圍備份，公開 repo 不能當私有檔案保險箱。

## 6. 2026-10-19 清理請求及執行邊界

- 使用者希望停用／清理 Windows 本機族譜資料，並在 GitHub 留下重啟紀錄。
- GitHub 能保留**目前此公開 repo 的空白填報程式**及本安全版交接文件；私人完整 ZIP **沒有上傳 GitHub**，其可恢復副本留在私人 Google Drive。
- **尚未刪除 Windows `D:\族譜`**：本對話無法直接讀取或刪除使用者電腦上的檔案；不能把對話暫存檔清除說成 Windows D 槽已清除。
- 若要由主編自行清理，只針對已明確核對且獨立備份的 `D:\族譜` 專案資料夾進行；不要刪除整個 D 槽、其他專案或雲端來源。先確定可從雲端**下載、解壓、開啟**，再執行本機清理。
- 若雲端無法還原，應停止不可逆刪除並保留剩餘副本；「列得到檔名」不是等同備份可恢復。
